## Commands

```sh
npm run dev                       # dev server on http://localhost:8080
npm run build                     # production build into .output/ (via Nitro)
node .output/server/index.mjs     # serve the production build (PORT env var sets the port)
npx tsc --noEmit                  # typecheck; dev and build strip types without checking them
npm run lint                      # ESLint, with Prettier formatting enforced as lint errors
npm run format                    # apply Prettier formatting
```

npm is the package manager (`package-lock.json`). A fresh `npm install` takes 10+ minutes on this machine, so run it in the background. No test framework is set up yet.

## Architecture

TanStack Start (server-rendered React) with TanStack Router **file-based routing**, not Next.js. Every file in `src/routes/` is a route; the naming conventions are in `src/routes/README.md`. `src/routeTree.gen.ts` is regenerated by the router plugin on every dev/build run; edit routes, and the tree follows.

- `src/routes/__root.tsx` is the HTML shell for every page: default `<head>` meta (each route's own `head()` overrides it), Google Fonts links, the stylesheet, the 404 and error boundary components, and the React Query provider.
- `src/router.tsx` creates the router and puts a React Query `QueryClient` into router context.
- Server path: `vite.config.ts` points TanStack Start's server entry at `src/server.ts`. It wraps the real handler and turns SSR crashes (including the ones h3 swallows into a JSON 500) into the static HTML page from `src/lib/error-page.ts`; `src/lib/error-capture.ts` recovers the original error for logging. `src/start.ts` adds request middleware that does the same for thrown errors. Nitro packages all of it and runs only during `build`.
- Server-only modules are named `*.server.ts` or import `@tanstack/react-start/server-only`. ESLint rejects the Next.js `server-only` package.

Styling is Tailwind v4, configured CSS-first in `src/styles.css` (there is no `tailwind.config.js`). Theme tokens are CSS variables on `:root` with `.dark` overrides, exposed to Tailwind through `@theme inline`; custom utilities are declared with `@utility`. Dark mode is the `.dark` class on `<html>`.

shadcn/ui components ("new-york" style, `components.json`) live in `src/components/ui/`, most of them currently unused; add more with `npx shadcn@latest add <component>`. `cn()` is in `src/lib/utils.ts`, and `@/` resolves to `src/`.
